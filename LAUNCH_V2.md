# HELIX-FT v2 — launch and evaluation guide

This is an operational guide to the scripts on the `Training_v2` branch, not a promise
that a complete run will succeed at a particular cost or duration. Training requires a
GPU environment, accepted access to the Llama base model, access to the configured
BrainHealthAI datasets/artifacts, and substantial storage. Verify current provider,
model, dataset and license terms before use. This guide does not authorize or imply a
new training run or model publication.

## Before launch

1. Review the configured paths and stage ordering in `launch_v2.sh` and each stage
   script. The intended chain merges SFT-Big into Llama-3.1-8B-Instruct, then runs Stage
   A continued SFT, Stage B SASR, Stage C CoT, and configured evaluation/publishing
   steps. Ensure the actual input artifacts match that chain.
2. Ensure the environment can access `BrainHealthAI/MedUnified`,
   `BrainHealthAI/MedQA-Darija-MCQ-500` when running Darija evaluation, the base model,
   and any required Dorosz knowledge-graph file. Dataset availability and access may
   change; verify before allocating compute.
3. Install dependencies from `requirements.txt` in a suitable isolated environment.
   Set credentials only in the runtime's secret/environment facility. Never paste
   `HF_TOKEN`, `WANDB_API_KEY`, or other secrets into source files, command histories,
   logs shared outside the team, or commits.
4. Confirm output and cache paths have sufficient space and are not shared with
   unrelated workloads. Start with the smallest relevant stage/evaluation where the
   scripts support it; inspect logs and outputs before proceeding.

## Launch and resume

The repository's orchestration entrypoint is:

```bash
bash launch_v2.sh
```

The script supports `START_AT`, `STOP_AT`, `SKIP_PUSH`, and the logging configuration
shown in the script. Check the current `launch_v2.sh` before using these controls: stage
indices and behavior are implementation details and can change. A resume is safe only
when the expected upstream artifacts exist and correspond to the same run/configuration.
Use a persistent terminal session if needed, and preserve the full logs and exact
configuration alongside each result.

Publishing is a separate external action. Before enabling any push, inspect the target
repository, visibility, files, metadata and credentials. `SKIP_PUSH=1` is available for
running without the final push, subject to the script's current behavior.

## Evaluation workflows

- `evaluate_v2.py` runs generation-based MCQ scoring (letter parsing) and generation
  metrics. Its interface and sample limits are defined by that script; it is slower and
  methodologically distinct from log-likelihood scoring.
- `reeval_loglikelihood.py` evaluates MCQ answers by scoring answer-letter tokens.
- `final_eval.py` combines log-likelihood MCQ scoring and free-form generation metrics.
  Its current benchmark loaders and methods define what its output means.

Do not compare outputs from these harnesses as if they were the same evaluation. Record
script revision, model/base/adapter revisions, dataset revisions and split, item order or
selection rule, limits, prompt/scoring method, and per-item predictions. The published
HELIX results are in the [pinned `eval_v2.json`](https://huggingface.co/BrainHealthAI/MedQA-Llama3.1-8B-HELIX-v2/blob/dd0b813bde0e17b3a67fa90c4304a94f1f3c0130/eval_v2.json);
they are historical outputs, not results generated by following this guide. README
documents the denominators and evidence limitations.

## Interpretation and decision gates

Training loss, reward curves, SB_CS, and automatic benchmark accuracy are development
signals, not clinical safety or efficacy gates. SB_CS is part of the Stage B reward and
is also reported as an evaluation metric; a rise in it alone cannot establish medical
correctness or a causal SASR gain. The Dorosz-based penalty checks a limited drug-name
vocabulary and is not a general hallucination detector.

Do not use the historical expectations sometimes associated with this pipeline (specific
GPU hours/costs, score gains, superiority, or state-of-the-art claims) as measured facts:
the pinned result file does not substantiate them. A defensible model comparison needs
the same independently held-out items, prompts, scoring code and model lineage, with
per-item paired results, uncertainty and documented ablations. Benchmark outcomes do
not replace physician review or an independent clinical evaluation.

Before any research conclusion, check for duplicated/overlapping cases and translations
across all training stages and evaluation splits, and document dataset provenance and
selection. For the medium-term multilingual track, use source-linked EN/FR/Darija cases
with translation review and physician adjudication. These are research requirements, not
features supplied by the current launch scripts.

## Model and license boundary

HELIX-v2 follows the merge-and-adapter lineage described in the README. Do not load its
adapter against raw Llama unless the artifact metadata and inference setup explicitly
support that pairing. BrainMed-8B is a separate model lineage; the Brain Health
application is a separate integration/deployment. Neither is established by successfully
launching this training repository. Review all upstream model, data and dependency terms;
repository-level licensing does not grant rights beyond them.
